## 🐛 Bug 列表

### Bug #1 — [P2 一般] 暗色模式 CSS 不响应 JS 类名切换

**描述**：`layout.tsx` 中的脚本会基于 `localStorage('somme-theme')` 给 `<html>` 添加 `.dark` 类，但 `globals.css` 中暗色模式只使用了 `@media (prefers-color-scheme: dark)` 媒体查询，没有 `.dark` 类选择器。

**复现步骤**：
1. 在系统偏好中设置为浅色模式
2. 手动在 localStorage 中设置 `somme-theme: dark`
3. 刷新页面

**期望行为**：页面应该切换到暗色模式  
**实际行为**：页面仍然显示浅色模式（CSS 不响应 `.dark` 类）

**修复建议**：在 `globals.css` 中添加 `.dark` 类选择器，或改用 `html.dark` 前缀来覆盖 CSS 变量：
```css
html.dark {
  --wine-deep: #C75B8E;
  --wine-cream: #1E1A2B;
  /* ... */
}
```

---

### Bug #2 — [P2 一般] `h-screen` 在移动端 Safari 可能导致底部被遮挡

**描述**：主容器使用 `h-screen`（100vh），在移动端 Safari 中 100vh 包含地址栏高度，当地址栏可见时底部输入区域可能被部分遮挡。

**复现步骤**：
1. 在 iOS Safari 中打开页面
2. 地址栏展开状态下查看底部输入区域

**期望行为**：输入区域始终完整可见  
**实际行为**：可能被 Safari 地址栏遮挡

**修复建议**：改用 `h-dvh`（dynamic viewport height）或添加 CSS：
```css
.main-container { min-height: 100dvh; }
```

---

### Bug #3 — [P2 一般] 图片 HEIC 转换依赖客户端动态 import

**描述**：`heic2any` 库通过动态 `import()` 加载。如果用户网络较慢或 CDN 分块加载失败，HEIC 图片处理会静默失败（只有 console.error），用户看不到任何反馈。

**复现步骤**：
1. 在 iPhone 上拍摄 HEIC 格式照片
2. 在网络较差的环境下上传
3. 动态 import 失败

**期望行为**：显示错误提示"图片格式转换失败，请重试"  
**实际行为**：静默失败，无 UI 反馈

**修复建议**：在 `handleImageFile` 的 catch 块中添加 Toast 提示：
```ts
} catch (err) {
  console.error("Image processing failed:", err);
  setToast("图片处理失败，请重试");
}
```

---

### Bug #4 — [P3 建议] 智能分流按钮的触发条件过于依赖关键词

**描述**：`detectWineActions` 检测 AI 是否识别了酒，依赖硬编码关键词列表（"识别""这款酒""这是一款""酒标"等）。如果 AI 用不同措辞描述酒款，按钮可能不会出现。

**复现步骤**：
1. 上传一张酒标图片
2. AI 用非标准措辞回复（如直接说酒名不含关键词）
3. 想买/正在喝按钮不出现

**期望行为**：只要 AI 识别了酒，就显示分流按钮  
**实际行为**：依赖关键词匹配，可能遗漏

**修复建议**：考虑在 system prompt 中强制 AI 使用特定标记（如 `[WINE_IDENTIFIED]`），或放宽检测条件（只要有图片上下文且回复超过一定长度即可显示按钮）。

---

### Bug #5 — [P3 建议] API 空消息数组返回 Gemini 400 错误，错误信息不够友好

**描述**：当 `messages` 为空数组 `[]` 时，通过了 `!messages || !Array.isArray(messages)` 的校验，但空的 `geminiContents` 传给 Gemini API 会返回 400 错误。

**复现步骤**：
```bash
curl -X POST https://app-nu-seven-15.vercel.app/api/chat \
  -H "Content-Type: application/json" \
  -d '{"messages":[]}'
```

**期望行为**：返回友好的错误信息 "请至少发送一条消息"  
**实际行为**：返回 `{"error":"API error: 400"}`

**修复建议**：在验证逻辑中增加长度检查：
```ts
if (!messages || !Array.isArray(messages) || messages.length === 0) {
  return new Response(JSON.stringify({ error: "Messages array cannot be empty" }), { status: 400 });
}
```

---

### Bug #6 — [P3 建议] 味蕾画像推荐按钮去除 emoji 前缀可能匹配不到内容

**描述**：推荐按钮的 onClick 处理中，`rec.replace(/^[^\s]+\s/, "")` 会去除第一个空格前的内容（即 emoji 前缀），但如果翻译文本中 emoji 与文字之间没有空格或有多个空格，替换可能出错。

**复现步骤**：
1. 在中文模式生成推荐
2. 点击推荐按钮
3. 观察发送的消息是否正确

**期望行为**：发送完整的推荐查询  
**实际行为**：大部分情况正常，但 regex 逻辑脆弱

**修复建议**：直接使用完整文本发送，或在 i18n 中分离 emoji 和查询文本。

---

### Bug #7 — [P3 建议] localStorage 大图片可能超出配额

**描述**：`saveMessages` 会尝试将包含 base64 图片的消息存入 localStorage。虽然有降级处理（omit images），但如果对话很长且包含多张图片，首次保存可能触发 QuotaExceededError，导致短暂的性能延迟。

**复现步骤**：
1. 上传多张高分辨率图片并与 AI 对话
2. 消息历史增长到包含 3-5 张图片
3. 每次消息更新触发 `saveMessages`

**期望行为**：流畅保存不卡顿  
**实际行为**：首次 try 失败 → 第二次 try 省略图片，但会产生短暂延迟

**修复建议**：首次保存时就检测图片数据大小，超过阈值直接省略，或使用 IndexedDB 替代 localStorage 存储图片。
